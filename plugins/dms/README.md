# 桌面更新日志

插件由 PHP 直接读取本地文件和运行内核信息，使用项目现有的定时同步。无需 Python、playerctl、桌面采集服务或独立事件数据库。

## 支持的动态

- **安装 DMS 插件**：读取 plugins/*/plugin.json，本次新增的插件合并为一条动态。
- **插件版本变化**：比较清单中的 version，升级或回退都会记录；未声明版本的插件只检测安装。
- **运行内核变化**：使用 php_uname('r')，系统重启并实际切换内核后记录。安装内核包但尚未重启不会触发。
- **DMS 软件包版本变化**：直接读取 Arch 的 /var/lib/pacman/local，识别 dux-shell、dank-material-shell、dms 及其 -git、-bin 包。其他发行版或手动安装没有该记录时跳过这一项。这里展示安装的软件包版本，不代表已经重启桌面使用新版本。

音乐循环统计已移除。

## 配置

后台「动态插件 → 桌面更新日志」填写 **DMS 配置目录**，例如：

```text
/home/用户名/.config/DankMaterialShell
```

该目录下必须有可读的 plugins 子目录。保存并启用后，默认每分钟检查一次，也可以手动同步。首次同步或更换配置目录只建立基线，不发布历史信息。一次同步内的安装、升级分别合并，内核和 DMS 版本变化单独记录。

基线保存于项目数据库，只有动态入库成功后才推进；中途失败后重试由核心去重。不会公开完整路径、仓库地址、桌面设置、播放器内容或截图。插件升级以清单版本为准，版本号未变的代码变动不会发布。安装后又在两次同步之间卸载的插件无法被检测到。

## 部署与迁移

建议博客运行在桌面所在的机器上。Docker 部署需给网站和独立 sync 服务都挂载可读的 DMS 配置目录；插件目录中的符号链接目标也需可读。若要检测 Arch 的 DMS 软件包版本，还需将宿主 /var/lib/pacman/local 只读挂载到容器同一路径。

内核信息属于 PHP 所在的运行环境。Linux 容器通常与宿主共享内核，虚拟机和远程服务器则不能代表本地桌面的内核。

从旧采集版切换时，在桌面执行：

```bash
systemctl --user disable --now muke-dms.service
```

随后在后台填写 DMS 配置目录。插件自动清理旧事件库路径、游标和音乐限额配置；已有动态保留。旧事件数据库不再使用，可自行归档，插件不会删除它。
