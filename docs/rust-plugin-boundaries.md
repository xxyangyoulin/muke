# Rust 插件边界

2026-11-26。适用于 `rust-rebuild` 分支，当前五个插件均已接入接口；壁纸已接入扫描、图库、图片读取、批量上传和管理员删除，完整导出与备份仍待迁移。

插件采用内置 Rust 模块，通过 `Plugin` trait 和一个显式注册表接入。新增后端插件需要编译发行包；不执行 PHP，也不引入动态库 ABI、脚本引擎或独立插件进程。

## 代码归属

| 位置 | 职责 |
| --- | --- |
| `src/plugins/mod.rs` | 插件接口与注册、配置校验、公开清单、管理接口分发、定时需求声明 |
| `plugins/<id>/backend/` | 插件声明、自有表迁移、解析与同步、数据查询、管理操作、媒体引用和衍生文件清理 |
| `plugins/<id>/frontend/` | 插件卡片、页面、交互及样式 |
| `src/plugins/import.rs` | 插件共用的原图下载、导入去重、事务提交及待完成媒体恢复 |
| `src/tasks.rs` | 持久队列、领取、去重、资源互斥、进度、取消、恢复、定时记录、管理员 SSE |
| `src/network.rs` | 下载并发、字节与时间限制、地址校验、逐跳重定向检查、代理连接固定到已校验 IP |
| `src/media.rs` | 图片格式检测、压缩进程限制、通用上传引用与清理 |
| 核心 API 和前端加载器 | 认证、CSRF、统一分发和按清单加载资源 |

RSS 的表名、来源 ID、订阅地址规则、解析、30 天清理策略以及 `rss-thumbs` 目录只出现在其插件模块中。首页过滤读取插件声明的 `timeline_field`，不在核心 SQL 中单独判断 RSS。核心图片删除、缩略图查询通过注册表调用插件钩子；停用插件仍参与历史媒体解析和清理。

插件自己的后台表由自己的迁移入口管理。核心业务迁移不添加 `rss_feeds` 等插件表。前端核心不导入具体插件脚本，由公开清单中的资源地址加载；插件通过现有 `MKBLOG.registerCard` / `registerPage` 注册展示能力。

## 源码与前端目录

```text
Cargo.toml                根目录 Rust 工程
Cargo.lock                依赖锁定
src/
  plugins/mod.rs          插件接口与注册表
  tasks.rs                统一任务执行器
migrations/               核心数据库迁移
frontend/
  index.html              独立页面入口
  assets/
    app.js                启动和路由
    registry.js           插件前端注册接口
    views/                首页、文章、编辑器、后台、任务页
    components/           评论、图片浏览、编辑器等通用组件
    lib/                  API、状态、导航、生命周期、插件加载
    style.css             核心样式
plugins/
  rss/
    backend/
      mod.rs              RSS Rust 实现
      manifest.json       RSS 配置和页面声明
    frontend/
      plugin.js           RSS 页面、卡片和管理面板
      plugin.css          RSS 专属样式
```

Rust 主工程位于项目根目录，直接执行 `cargo build`、`cargo test` 和 `cargo run -- serve`。迁移期间 `src/` 中原有 PHP 文件保留用于回归，Rust 仅编译 `.rs` 模块。

核心前端集中维护，只处理通用页面和公共组件。插件前端通过 `/assets/...` 导入需要的公共模块，通过 API 获取数据，并使用注册接口扩展页面。通用代码不会为某一个插件导入专属文件。

前后端分离指运行时通过 API 通信，不要求把同一插件的源码分散到两个工程目录。后端注册表使用 Rust 模块路径编译 `plugins/<id>/backend/mod.rs`，目前无需为每个插件建立独立 crate。将来只有确实需要独立发布或共享时，再拆 Cargo workspace crate。

开发时不复制插件前端。服务根据注册表将 `plugins/<id>/frontend/` 挂载到 `/plugins/<id>/`，只提供此公开目录，插件 Rust 源码和配置文件不会被静态文件路由公开。`frontend/` 与 `plugins/` 在开发目录和发行包中保持同级；`--frontend /path/to/frontend` 对应的插件目录为 `/path/to/plugins`。

发行包应保留核心 `frontend/` 与各插件的 `plugins/<id>/frontend/`，不包含插件 Rust 源文件。Netlify 导出应将相同源码目录的资源收集到 `/plugins/<id>/` URL；导出实现仍待完成。这样无需维护另一份插件前端源码。

迁移期间插件目录根部原有 `plugin.php`、`plugin.js`、`plugin.css` 仅供 PHP 主线回归；Rust 从新 `backend/` / `frontend/` 目录读取。PHP 正式切换完成后再删除旧实现，不把它作为长期兼容层。

## 任务与一致性

插件只声明任务参数、执行过程和下一次执行间隔。调度器统一持有任务表和定时表，插件同步实现不直接领取任务或启动常驻进程。

- 同一插件的同步任务共用资源标识，串行领取；相同参数的活动任务复用任务编号。不同插件可并发。配置、移除和清空使用同一插件操作锁；任务执行中返回冲突，管理员可先取消任务，避免刚清空的内容又被同步写回。
- RSS 在一个同步任务内部最多同时处理四个源，下载总并发为四，图片处理总并发为二。普通 API 不等待后台任务完成。
- 网络和压缩不持有内容写锁或 SQLite 写事务。入库时重新检查订阅登记、去重键及墓碑。
- 插件执行接收取消令牌与进度接口。取消后等待工作退出并清理临时目录，才写入终态；已经完成的条目事务保留，下次通过去重继续。
- RSS 和微博文件落地前登记待完成媒体；进程意外中断后，插件启动恢复会清理没有内容引用的残留媒体。
- 备份使用统一内容写锁协调数据库与媒体修改。备份实现仍在后续阶段，当前不能宣称已经提供完整备份一致性保证。

目前接口覆盖的是已迁移的实际需求。静态导出、备份目录声明、其他插件媒体协议和事件会随对应迁移加入明确接口，并保留在插件模块内部；不会把这些插件细节写入核心来绕过接口。

桌面更新日志使用核心的普通动态展示，不需要专属前端资源。插件只有声明 `frontend` 时才挂载并加载对应资源。桌面快照与变化动态在同一事务提交；目录不可用、清单损坏或数据库写入失败时保留旧快照。事件去重键保持 PHP 的 JSON 编码和哈希语义。

微博的 RSS/Atom 解析、状态 ID 去重、Referer、图片尺寸过滤和卡片资源均在插件目录中。原始图片沿用普通上传存储规则；保存配置通过通用 `config_changed` 钩子在同一事务更新已有动态，失败时配置与内容一起回滚。网络层支持可选 Referer，同源跳转保留，跨源跳转后移除；每一跳仍检查目标地址。

豆瓣的页面解析、电影信息、文案模板、分类和分页规则均位于 `plugins/douban/backend/`。微博与豆瓣共用导入模块，只传入来源、动态内容及临时媒体；公共模块不包含站点地址、分类、解析选择器或文案规则。RSS 保留自身的缩略图和媒体恢复策略。

## 当前缺口

壁纸上传位于 `plugins/wallpapers/backend/uploads.rs`，核心只负责 multipart 解析与插件上传分发。上传使用隐藏暂存文件和持久记录；批次登记与提交标记同事务写入，重启清理未提交文件或完成已提交缩略图发布，清理时不删除被外部替换的同名文件。完整导出和备份钩子仍待迁移。管理员删除的持久日志及恢复代码位于 `plugins/wallpapers/backend/operations.rs`；重启按数据库是否保留图库行决定恢复或清理暂存文件，目录离线时保留记录，恢复目标有其他文件时不覆盖。其扫描、引用解析和图片响应通过通用插件接口接入，核心不识别 `wall:`、壁纸表或目录配置；旧配置键映射和页面依赖配置由清单声明。

RSS 的 favicon 首次下载和旧条目身份回填尚未实现；已有 favicon 引用可以读取和清理。插件清空/移除已接入统一接口；完整静态导出和备份仍需继续迁移。Atom XHTML 内容、非 UTF-8 XML 和非标准日期还需补充兼容测试。当前实现不作为完整插件迁移完成的标志。

静态导出的 `export_source` 钩子只返回插件已校验的本地媒体路径；壁纸目录和 `wall:` 解析留在壁纸插件。核心统一复制暂存副本、校验真实图片格式并生成静态描述符，不调用插件 HTTP 图片端点。`export_snapshot` 在内容读锁内收集插件公开数据和额外媒体引用，`export_data` 在锁外将快照转为现有静态前端的数据结构；RSS 和壁纸已实现这些钩子，全量图库不依赖是否有关联动态。插件无 JavaScript 页面仍待接入。
