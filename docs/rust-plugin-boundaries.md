# Rust 插件边界

内置插件通过 `Plugin` trait 接入，第三方插件使用[独立进程协议](rust-external-plugins.md)。核心只提供通用能力，插件业务留在插件仓库或目录内。

## 目录职责

| 位置 | 职责 |
| --- | --- |
| `src/plugins/mod.rs` | 插件接口、配置校验、API 分发与调度声明 |
| `src/plugins/registry.rs` | 运行时注册表与插件操作锁 |
| `src/plugins/install.rs` | 获取源码、编译、自检与安装 |
| `src/plugins/remote.rs`、`process.rs` | 独立插件协议、进程调用与取消 |
| `src/plugins/import.rs` | 通用图片下载、动态去重和事务入库 |
| `src/tasks.rs` | 持久任务队列、进度、日志、取消与恢复 |
| `frontend/` | 核心页面、公共组件和插件加载器 |
| `plugins/<id>/backend/` | 内置插件的迁移、同步、查询、媒体与导出逻辑 |
| `plugins/<id>/frontend/` | 内置插件页面、卡片和样式 |

第三方仓库独立维护 `Cargo.toml`、`plugin.json`、后端源码和可选 `frontend/`；不引用主项目 Rust 类型或数据库表。

## 接入规则

- 核心不按插件 ID 判断业务。配置字段、路由、资源、同步间隔通过清单和接口声明。
- 内置插件管理自己的业务表、解析规则和资源目录；第三方插件通过协议使用配置、JSON 状态、动态导入及公开数据接口。
- 前端按清单加载资源，通过 `MKBLOG.registerCard` / `registerPage` / `registerWidget` 注册；核心不导入具体插件脚本。
- `/plugins/<id>/` 只暴露插件前端目录。内置插件后端编译进 MUKE；独立插件程序保存在数据目录中。
- 静态导出由插件提供数据、HTML 和媒体引用，核心统一生成站点；完整备份保存插件声明的资源及独立插件安装文件。

## 任务与一致性

插件只声明任务参数、执行逻辑和同步间隔，由统一队列调度。同一插件的同步、配置和更新互斥，不同插件可并发；安装任务串行。

网络下载和编译不持有内容写锁。提交内容、切换安装及完整备份由内容锁协调；导出固定插件版本，避免更新期间混用资源。

取消会终止插件进程组并清理任务临时目录。已提交条目保留，下次同步按来源键去重；编译和自检成功后才替换旧安装。
