# Rust 重构进度

2026-11-26，`rust-rebuild` 分支。当前已实现核心写入流程、原有前端入口，以及统一任务和 RSS 的第一条完整同步链路。仍处于开发阶段，尚不能替代 PHP 正式站点，也没有生成正式 Rust 发行包。功能边界以本文列出的待办为准。

## 已实现

- Axum / SQLx，兼容 PHP 核心 schema 4；新目录自动建库。使用 TOML / 环境变量和数据库设置，不在运行时加载 PHP 配置。
- 原有原生 ESM 前端已复制到 `frontend/assets/`，通过独立 API 登录、发布动态、编辑文章、查看修订及修改设置。
- 持久 Cookie 会话、CSRF、受限首次建号、登录限速、Argon2 新密码、PHP bcrypt 旧密码校验、退出与修改密码撤销会话。
- 普通上传图的 WebP 缩略图缓存：沿用尺寸/质量设置、同图请求串行复用、源文件与设置变化失效、生成后重新检查原图、引用删除时清理缓存目录；RSS 插件自有缩略图优先，处理失败仍可读取原图。
- AVIF 上传会返回尺寸与字节数，支持原图访问、WebP 缩略图及引用删除清理。Gravatar 通过受限网络客户端下载并校验图片，按哈希原子缓存，同一头像并发请求复用下载，拒绝非法哈希及缓存符号链接。
- 头像与封面上传/移除：WebP 输出、可配置方形头像、1500×500 居中封面，处理成功后原子替换，失败保留旧图；临时文件随请求清理，启动清理异常退出残留，图片端点阻断符号链接越界。
- 文章渲染与摘要集中在 `src/render.rs`，预览、详情及列表共用。Markdown 保留代码语言、表格对齐及单元格文字间隔，按旧版规则将裸 HTTP(S) URL 转为链接并排除代码、已有链接和图片说明，封面按有效上传文件名生成缩略图地址。
- 动态/文章 CRUD、草稿权限、修订保存与恢复、上传及引用清理、搜索与游标分页、原生评论审核、点赞、资料和设置。
- 通用 SQLite 任务队列：图片处理和插件同步，最多四个运行任务；图片并发二、同一插件同步互斥、活动任务去重、定时计划、取消与中断恢复。
- 管理员任务列表和 SSE；会话退出/失效时关闭事件流，重连查询持久任务快照。任务界面可取消排队和运行中的任务。
- RSS 插件独立模块及清单：添加/退订、RSS/Atom/RDF 解析（含 Atom XHTML 正文与图片）、单源/全源/历史同步、源筛选、去重与墓碑；默认开启 30 天过期清理，同时清理原图和缩略图。首次同步下载来源图标，成功后事务回填历史条目身份；下载失败继续导入并在下次同步重试，图标沿用 RSS 压缩限额与媒体恢复日志。
- 壁纸已接入后台扫描、首次只登记、后续发动态、目录离线保护、移除缺失文件关联记录、图库与原图/缩略图访问；支持原有配置键、秒级调度、任务取消和事务回滚。管理员删除通过持久日志协调源文件与数据库，支持失败回滚、重启恢复及离线等待；壁纸上传支持横竖图归档、重名保护、批量单动态、原图/缩略图事务登记与上传中断恢复。
- 豆瓣插件已接入统一任务：看过/想看/在看分类、普通 30 条与可配置历史上限、最多 20 页、电影元数据/文案模板、封面下载、去重与墓碑；日期沿用站点时区的 21:00，前端保留电影卡片。
- 微博插件已接入统一任务：RSS/Atom 同步（含 XHTML 正文与图片）、历史上限、原始图片下载和尺寸过滤、去重与墓碑、配置变更即时更新已有动态、卡片资源、取消及中断媒体恢复。
- RSS 与微博支持 XML 声明编码及 UTF-8/UTF-16 BOM，公共解码模块位于 `src/plugins/feed.rs`；夹具覆盖 GBK/GB2312、Shift_JIS、ISO-8859-1 与双字节序 UTF-16，未知编码及损坏字节会报错。
- RSS 与微博按站点时区读取常见无时区日期，支持日期、分钟、秒及常见带偏移格式；标准 RFC 日期保留原时区。Atom 的纯文本、HTML、XHTML 标题分别读取，避免富文本标题丢失或把字面量当标签删除。
- RSS 原图小于 100 KiB、缩略图小于 50 KiB，严格检查实际字节数。普通上传不套用 RSS 限额。
- 插件清空、移除、停用后的历史媒体解析和引用清理；桌面更新日志已迁移，首次建立基线，后续检测插件、内核和 DMS 包变化，快照与事件事务提交。
- 下载限制并发、超时和响应大小；管理员显式配置的订阅地址允许内网，正文图片禁止内网和保留地址，每次重定向重新校验。通过静态链接的 libcurl / OpenSSL 保留代理 CONNECT 到已校验 IP 的行为，不依赖 curl 命令。
- 图片处理使用受限 ImageMagick 子进程，取消会终止并回收子进程；Linux 父进程死亡通知防止服务 SIGKILL 后残留压缩进程。

插件前后端同放 `plugins/<id>/backend/` 与 `plugins/<id>/frontend/`，核心前端保留在 `frontend/`。开发时直接提供插件前端目录，不复制源码。插件约束与接口归属见 [Rust 插件边界](rust-plugin-boundaries.md)。RSS 自有表、保留策略、图片缓存路径位于插件目录，核心不包含 RSS 分支。

## 本地运行

当前需要 Linux、Rust 1.91.1+、C/C++ 编译工具链及 Perl（构建静态网络依赖），运行时需要 `magick`。测试另需 PHP、Python 3、Node 22+ 和 Chrome。正式发行包仍待制作，届时不要求用户安装编译工具链。

在仓库根目录，使用一个新的临时数据目录：

```sh
cargo build --locked
target/debug/muke --data-dir /tmp/muke-rust-demo serve --frontend frontend
```

访问 `http://127.0.0.1:8785/admin` 创建测试管理员。不要指向生产 `var/`，不要让 PHP 与 Rust 同时修改同一份数据。

可选 TOML 示例：

```toml
listen = "127.0.0.1:8785"
data_dir = "/tmp/muke-rust-demo"
frontend = "frontend"
timezone = "Asia/Shanghai"
setup_hosts = ["127.0.0.1", "::1"]
cookie_secure = false
```

通过 `--config /path/to/muke.toml` 加载。HTTPS 部署时应设置 `cookie_secure = true`。前后端独立部署可由反向代理将 `/api`（包含 SSE）及 `/image` 转发到 Rust，保持同源 Cookie。

默认任务库在 `data_dir/runtime/tasks.sqlite`；可用 `--work-dir` 指定其他目录，但任务目录不能包含内容目录。实例锁位于内容目录，同一内容目录不能启动多个调度实例。

本机 CLI：

```sh
target/debug/muke --data-dir /tmp/muke-rust-demo tasks
target/debug/muke --data-dir /tmp/muke-rust-demo thumbnail /tmp/muke-rust-demo/uploads/已存在的图片文件名.png
target/debug/muke --data-dir /tmp/muke-rust-demo cancel 任务ID
```

独立图片任务结果位于 `runtime/image-任务ID/`。正常退出取消运行任务，保留排队任务；异常退出后未完成任务标记 `interrupted`，清理临时产物。不会盲目自动重试上次执行；可手动重提，启用的插件会在下个定时计划继续同步。

[首次基线](rust-baseline-2026-11-26.json) 仅代表最初的只读原型，不能代表当前版本性能。测试使用小夹具、PHP 内置服务器、Rust debug 构建；慢子进程场景不是 CPU 饱和压测。正式性能结论仍需 release 构建和更大数据量。

`src/export/data.rs` 已串联快照、媒体复制、释放内容锁、缩略图处理及 JSON 写入，生成 `assets/content.json` 和 `assets/articles.json`。文章使用共用渲染/摘要模块，图片及链接属性转换为静态地址，代码示例文字保持原样；文章缺失引用图片时中止生成。首页隐藏来源只从首页列表排除，插件独立页仍有完整数据，已获批评论随对应内容输出。测试覆盖实际文件、媒体路径、锁释放、草稿隔离及取消。
