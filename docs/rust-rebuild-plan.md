# Rust 重构计划

日期：2026-11-26。状态：**已完成**。2026-11-27 全部阶段实现完毕（P0–P5，除需真实凭据的在线验证与正式发行标签外），数据已迁移并在本机完成生产切换（Rust 接管原 PHP 端口，PHP 保留回退）。实现与验证记录见 [原型进度](rust-prototype.md)，安装迁移见 [安装指南](rust-install.md)。

## 目标与范围

重构目标是简化安装、统一后台任务管理，并让同步、图片处理、部署等任务同时运行时不阻塞页面与后台操作。前后端独立维护，用户仍可通过一个发行包、一个启动命令运行完整应用。

第一版保留现有功能、原生 JavaScript 前端、SQLite 数据库和 Netlify 静态发布方式。不会同时更换前端框架、数据库或图片处理引擎，也不引入 Redis、消息队列、微服务、WASM 插件平台或多实例调度。

当前代码基线是 PHP 0.3.0 及其后的界面调整。`src/`、`plugins/`、`bin/` 合计约 4,300 行 PHP，前端约 2,900 行 JavaScript，仅用于判断规模，不作为工期换算依据。

## 架构与部署

采用一个 Rust 应用，内部划分 HTTP API、业务模块和任务执行器。建议技术组合：Axum、Tokio、SQLx/SQLite、Reqwest、Serde。依赖版本在原型阶段确认并锁定。

```text
frontend/                 核心页面、后台、编辑器、公共组件与资源
plugins/<id>/
  backend/                插件 Rust 实现、自有表和配置声明
  frontend/               插件页面、卡片、交互和样式
Cargo.toml / Cargo.lock   根目录 Rust 工程及锁定依赖
src/                      API、业务模块、任务调度、导出与 CLI
migrations/               核心数据库迁移
tests/                    接口、浏览器、迁移及故障恢复测试
docs/                     API 契约、安装与迁移说明
```

前端通过 API 获取运行配置、插件清单和业务数据，不依赖 PHP 拼装 DOM。插件导航和资源加载从明确的清单驱动。公开页面的元数据与静态烘焙由导出模板负责，保留 canonical、RSS、sitemap 和无 JavaScript 可读的静态页面。

| 运行方式 | 约定 |
| --- | --- |
| 默认一体部署 | 发行包包含 Rust 程序和前端资源；`muke serve` 同时提供静态文件、API 和后台调度 |
| 前后端独立部署 | 前端由 Nginx 等提供，`/api`、`/image` 和任务事件入口反向代理到 Rust，默认仍使用同源 Cookie |
| 本地开发 | 前端可独立启动，通过开发代理连接 Rust API，不要求生产用户安装 Node 或 Rust |
| Netlify 静态站 | 导出 HTML、JSON 和媒体；浏览时不连接 Rust，评论继续使用 giscus 等第三方服务 |

首版提供 Linux x86_64、ARM64 安装包、校验文件、systemd 示例和 Docker 镜像。移除运行时对 PHP、PHP-FPM、PM2 的依赖；ImageMagick 暂时保留，并由启动自检说明缺失依赖。首版不承诺完全无外部依赖或全平台支持，桌面更新日志插件保留其 Linux/Arch 特有能力边界。

前端资源采用随包目录，避免第一阶段额外引入资源嵌入与独立热更新机制。记录前后端协议版本，独立部署时检测不匹配并提示升级。跨站域名部署不作为首版默认路径。

## 前后端契约与兼容边界

- 先记录现有 `/api?action=...` 的请求、响应、状态码、Cookie、CSRF、分页游标和上传格式；Rust 直接实现这些协议，不为重写而同步重设计路由。
- 保留公开 URL、文章和动态 ID、图片引用 `up:` / 插件引用、插件 ID、来源去重键、墓碑、修订记录以及设置含义。
- giscus 保持仓库、分类和 `post:ID` / `article:ID` 映射，保留底部表单和部署时计数；不复制或重新建立讨论。
- 前端继续原生 ESM。动态模式读取 API，导出模式读取静态 JSON；运行模式明确，不让静态站依赖后端会话、管理接口或 SSE。
- 任务列表、详情、取消、事件流使用明确的数据结构；进度允许“已处理数量/阶段”，没有可靠总量时不伪造百分比。
- 会话使用 HttpOnly Cookie，保留 CSRF、登录限速及受限首次建号；迁移后重新登录，不迁移 PHP 会话文件。验证现存密码哈希算法的兼容性，不要求用户无故重设密码。
- 更换 Markdown 渲染器前验证换行、列表、代码块、链接、摘要和封面提取；富文本过滤和输出转义属于兼容验收的一部分。
- 移植远程抓取的内网限制、重定向检查、代理行为及跨域凭据隔离；不能只换 HTTP 库而丢失现有边界。

## 统一后台任务

### 状态与持久化

SQLite 保存待执行任务、执行记录和定时计划，SSE 只通知变化，不作为唯一状态来源。最少记录任务 ID、类型、资源标识、执行时间、状态、阶段进度、取消请求、起止时间和错误摘要；任务参数与日志不暴露令牌、密码。

基本状态为 `queued → running → succeeded / failed / cancelled`。执行中的取消先标记请求，待网络操作或子进程停止、资源清理完成后才进入 `cancelled`。重启发现未正常结束的任务记为 `interrupted`，随后按任务类型决定是否创建新的执行尝试，不承诺恰好执行一次。

同一数据目录只允许一个服务实例负责调度。领取任务、状态变更和定时计划更新在短事务中执行；CLI 的恢复、迁移等维护操作也检查实例锁。不让 PHP 和 Rust 调度器同时写正式数据。

### 并发与资源约束

| 工作类型 | 执行规则 |
| --- | --- |
| HTTP 页面与 API | 与后台任务分开调度，不在异步执行线程中运行压缩或大文件打包 |
| RSS 源、远程图片下载 | 使用全局网络并发上限；不同源可并发，同一源不重复同步 |
| 插件同步 | 同一插件任务不重叠；RSS 内部按源并发；去重检查和写入受事务或串行写入步骤保护 |
| 图片压缩 | 独立子进程并发上限，通过参数数组启动 ImageMagick，限制 CPU/内存压力 |
| 导出与部署 | 共享发布互斥资源，全站同时只运行一个发布流程；重复自动触发合并，执行期间的新变更保留下一次待办 |
| ZIP 打包与大文件操作 | 放到受限的阻塞执行环境，分阶段检查取消，不阻塞 HTTP 事件循环 |
| 备份 | 同时一个；取得数据库与媒体的一致快照，最小实现可在快照/归档期间暂停内容写入和媒体删除，公开读取仍可用 |
| 恢复与数据迁移 | 服务停止后离线执行，先恢复到空目录验证，再切换，不与在线写入并发 |

初始并发上限通过原型负载测试确定，先使用少量内部默认值，不为每种任务增加后台设置。SQLite 维持短写事务；网络请求和图片压缩不占用写事务。数据库连接数、busy timeout 和是否启用 WAL 在原型中验证，WAL 下的备份必须使用正确的快照方式。

进程内资源约束应采用固定获取顺序，避免任务持有一个锁等待另一个锁。保留现有对“导出失败不替换 dist”“数据库提交后清理媒体”的业务要求，Rust 类型系统不能替代这些约束。

### 取消、退出与恢复

- 待执行任务直接取消；执行中通过取消令牌停止网络请求、等待中的工作，并终止、回收本任务创建的图片处理子进程。
- 阻塞线程不能靠丢弃句柄终止；打包与复制按文件检查取消，在不可中断阶段显示正在取消，完成安全清理后再结束。
- 取消部署不代表远端发布已撤销。远端请求结果不明确时记录部署 ID 并核对 Netlify 状态，界面如实显示结果。
- 正常退出时停止领取新任务，在限定时间内等待或取消当前任务；超时退出后通过持久记录恢复，不能仅依赖内存队列。
- 重启后，同步任务完成去重检查后可重新排队；导出重新构建临时目录；部署先核对远端状态；备份清理未完成产物后再决定重跑；恢复任务不自动重试。
- 自动重试仅适用于有明确幂等保证的临时故障，并设置次数与退避上限。配置错误与权限错误记录失败，等待修正。
- SSE 仅管理员可访问，断线重连重新查询任务快照；服务端重启或事件遗漏不依赖无限事件回放恢复。限制事件频率，避免慢客户端拖住任务执行。

## 插件迁移

具体接口与代码归属见 [Rust 插件边界](rust-plugin-boundaries.md)。插件细节必须留在各自模块内，核心通过注册接口调用。

现有 `plugin.php` 包含可执行 PHP 回调，不能在纯 Rust 后端直接加载。第一版将 RSS、微博、豆瓣、壁纸、桌面更新日志迁移为内置 Rust 模块，继续支持后台开关与配置。

只抽取当前实际使用的公共能力：配置、同步、公开数据、媒体引用、导出、删除清理和必要事件。保留前端卡片/页面注册能力，不先设计通用动态模块 ABI。新增后端插件需要重新编译发行包，发布说明必须明确这个变化。

逐插件核对：同步去重与墓碑、历史记录、时间线开关、停用后的历史媒体、目录离线行为、删除关联文件、静态导出和备份目录。RSS 保持原图小于 100 KiB、缩略图小于 50 KiB，以及默认开启的 30 天过期清理规则。

## 数据迁移与回退

1. 保持业务表结构与标识，Rust 的任务表采用独立迁移；明确迁移版本所有权，不能让旧 PHP 在新库上重新执行不匹配的迁移。
2. 使用数据库和媒体副本开发、回归；SQLite 使用备份接口或停写后的完整副本，不能在线只复制主数据库文件。
3. 将 PHP 基础配置转换为 TOML/环境变量，保留数据库后台设置的优先级和外部壁纸目录映射。现有 `config.php` 由一次性 PHP 导出工具读取，Rust 不执行 PHP，敏感值不写入日志或版本库。
4. 兼容读取已有完整 ZIP 备份和内容 JSON；验证数据库完整性、资源清单、路径安全和外部目录重定位。保留旧备份原件。
5. 正式切换前停止 PHP Web 写入、PM2 同步和遗留部署进程，保存最终完整备份，在新目录恢复并启动 Rust，通过检查后切换入口。
6. 回退使用切换前备份和对应 PHP 代码，不直接将升级后的数据库交回旧程序。切换后若已产生新数据，需要先导出/核对这些数据；恢复旧快照会丢失这部分更新，不能宣称无损回退。

## 分阶段实施与验收

阶段门槛保持如下；P0 / P1 正在继续验证，部分 P2 与 RSS 链路已实现；阶段门槛尚未全部通过。实现位于独立的 `rust-rebuild` 分支，PHP 主线继续维护，阶段通过后再扩大范围。

| 阶段 | 交付 | 验收门槛 |
| --- | --- | --- |
| P0：基线与契约 | API 清单、脱敏数据夹具、当前性能与资源占用记录、功能覆盖表 | 完整 PHP 测试通过；记录硬件、数据量、请求负载和关键输出，为 Rust 对比建立基线 |
| P1：服务与任务原型 | Rust 服务、只读首页/文章 API、独立前端入口、持久任务、RSS 拉取与图片处理原型、任务 SSE | 不写正式库；网络抓取和图片处理同时运行时 API 保持响应；达到并发上限后排队；取消回收子进程；强制终止重启后任务状态明确且无重复入库 |
| P2：核心业务 | 登录、权限、动态/文章编辑、上传、修订、搜索、原生评论点赞、设置 | 原有前端核心流程通过；旧密码与数据可用；分页、权限、媒体引用、Markdown/富文本输出通过契约测试 |
| P3：插件与发布 | 五个插件、静态导出、giscus 计数、Netlify、自动部署、任务页 | 同步去重、RSS 限额与过期清理、目录离线保护通过；发布串行且新待办不丢；取消/失败保留旧产物；静态站断开 Rust 后仍可浏览和使用第三方评论 |
| P4：备份与迁移 | 完整备份、定时保留、空目录恢复、配置转换、退出与异常恢复 | 旧备份恢复验证通过；内容与资源对照一致；模拟备份/部署/清理中断和磁盘写入失败；在副本上完成一次迁移与回退演练 |
| P5：发行与切换 | 两种 Linux 架构的安装包、Docker、systemd、安装升级文档 | 干净环境无需 PHP/Node/Rust 工具链可启动；依赖自检清晰；CI、包校验、浏览器回归通过；完成正式切换前备份和检查 |

P1 以“统一任务且不拖慢页面”为主要决策点，未达到此目标时先修正执行模型，不继续大规模翻译业务代码。基准至少记录 API p95 延迟、进程及图片子进程总峰值内存、任务耗时、取消响应时间；正式指标在 P0 根据现有环境与负载确定，不预先承诺提速倍数。

## 测试与发布要求

- 复用现有 HTTP 和浏览器测试场景；PHP 内部调用、夹具改写和 Shell 启动测试按 Rust 执行方式重写，不声称原套件可直接全部复用。
- 外部 RSS、giscus、Netlify 使用可控本机夹具，覆盖分页、限流、超时、重复响应和不确定远端结果，CI 不依赖真实第三方服务。
- 内容与静态产物比较关注语义：链接、计数、权限、媒体引用、SEO 和无 JS 可读内容；忽略临时路径、运行时间等非确定字段。
- Rust CI 执行格式检查、Clippy、单元/集成测试、浏览器测试、迁移恢复和安装包自检；两个架构的产物至少验证启动与关键依赖，不能只验证交叉编译成功。
- 升级文档明确 PHP 插件不再直接加载、登录会话失效、配置转换方式和回退边界。Rust 正式版本号在发布阶段决定，本计划不触发发布。

## 工作量与下一步

按一名熟悉 Rust 与本项目的开发者全职投入估计：只读服务和任务原型约 1–2 周，核心管理功能累计约 3–4 周，完整功能、迁移演练与发行累计约 6–10 周。任务恢复、备份一致性或插件差异超出预期时应重新估算；这些是规划量级，不是交付日期承诺。

下一步补齐接口与渲染契约，并接入 RSS 网络任务、管理员任务事件流和真实混合负载测试；当前进度与范围见 [原型进度](rust-prototype.md)。
